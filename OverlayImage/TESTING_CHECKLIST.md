# OverlayImage Testing Checklist\n\n## Pre-Testing\n\n- [ ] Tweak built successfully: `make package`\n- [ ] `.deb` transferred to device\n- [ ] Installed via `dpkg -i`\n- [ ] SpringBoard resprung: `killall SpringBoard`\n- [ ] Device running iOS 18 (or compatible version)\n- [ ] Device has jailbreak support (Theos/Logos functional)\n- [ ] Photos library has test images available\n\n---\n\n## 1. Installation & Initialization\n\n### 1.1 Tweak Loads\n- [ ] After respring, no crashes in system.log\n- [ ] OverlayImage.dylib present in `/Library/MobileSubstrate/DynamicLibraries/`\n- [ ] Preferences plist exists at `/var/mobile/Library/Preferences/com.example.overlayimage.plist`\n\n### 1.2 OverlayManager Initializes\n- [ ] No error messages in Console app\n- [ ] Tweak does not cause SpringBoard to crash on startup\n- [ ] Tweak does not cause high CPU usage at idle\n\n---\n\n## 2. Image Selection\n\n### 2.1 Photo Picker Launch\n- [ ] Tap to trigger image picker (via preference app or tweak settings)\n- [ ] PHPickerViewController appears (iOS 14+) or UIImagePickerController (iOS < 14)\n- [ ] Can browse Photos library\n- [ ] Can select single image\n\n### 2.2 Permission Handling\n- [ ] On first launch, system prompts for Photos access\n- [ ] User can grant or deny permission\n- [ ] If denied, graceful error message shown (not crash)\n- [ ] If granted, picker works\n\n### 2.3 Image Display\n- [ ] After selection, overlay window appears immediately\n- [ ] Image displayed at correct aspect ratio (no distortion)\n- [ ] Image has no border\n- [ ] Image has no shadow\n- [ ] Background is transparent\n\n---\n\n## 3. Image Manipulation: Dragging\n\n### 3.1 Pan Gesture\n- [ ] Pan gesture recognizer active on image\n- [ ] Dragging image moves it smoothly\n- [ ] Movement is real-time (no lag)\n- [ ] Can drag to any position on screen\n\n### 3.2 Boundary Behavior\n- [ ] Image can be dragged partially off-screen\n- [ ] Image can be dragged back on-screen\n- [ ] No crashes when image reaches screen edge\n\n### 3.3 Drag Performance\n- [ ] Dragging at 60 FPS (or 120 FPS on ProMotion)\n- [ ] No frame drops during drag\n- [ ] CPU usage remains low (<10%) during drag\n\n---\n\n## 4. Image Manipulation: Pinch & Scale\n\n### 4.1 Pinch Gesture\n- [ ] Pinch gesture recognizer active on image\n- [ ] Pinching outward scales image up\n- [ ] Pinching inward scales image down\n- [ ] Scale is real-time (no lag)\n\n### 4.2 Scale Bounds\n- [ ] Minimum scale: 0.5x (cannot shrink below)\n- [ ] Maximum scale: 3.0x (cannot grow above)\n- [ ] Scale clamps correctly at boundaries\n\n### 4.3 Scale Performance\n- [ ] Pinch at 60-120 FPS (no drops)\n- [ ] No jank or stuttering during scale\n- [ ] CPU usage remains low (<10%) during pinch\n\n### 4.4 Combined Gestures\n- [ ] Pan + Pinch simultaneously works (no crashes)\n- [ ] One gesture doesn't interfere with other\n\n---\n\n## 5. Persistence\n\n### 5.1 Position Saved & Restored\n- [ ] Drag image to new position\n- [ ] Kill SpringBoard: `killall SpringBoard`\n- [ ] After respring, image appears at saved position\n- [ ] Position persists across multiple kill/respring cycles\n\n### 5.2 Scale Saved & Restored\n- [ ] Pinch to scale image (e.g., 1.5x)\n- [ ] Kill SpringBoard\n- [ ] After respring, image has same scale\n- [ ] Scale persists across multiple cycles\n\n### 5.3 Visibility Saved & Restored\n- [ ] Hide overlay (toggle visibility off)\n- [ ] Kill SpringBoard\n- [ ] After respring, overlay remains hidden\n- [ ] Show overlay (toggle visibility on)\n- [ ] Kill SpringBoard\n- [ ] After respring, overlay visible again\n\n### 5.4 Tap-Through Mode State\n- [ ] Enable tap-through mode\n- [ ] Kill SpringBoard\n- [ ] After respring, tap-through still enabled\n- [ ] Disable tap-through mode\n- [ ] Kill SpringBoard\n- [ ] After respring, tap-through disabled\n\n---\n\n## 6. Tap-Through Mode\n\n### 6.1 Tap Outside Image (Tap-Through Enabled)\n- [ ] Enable tap-through mode\n- [ ] Tap on overlay but outside image bounds\n- [ ] Underlying app receives tap (app responds)\n- [ ] Overlay does NOT respond to tap\n\n### 6.2 Tap Inside Image (Tap-Through Enabled)\n- [ ] Tap on image itself\n- [ ] Overlay receives tap\n- [ ] Underlying app does NOT receive tap\n- [ ] Can drag/pinch image without passing through\n\n### 6.3 Tap-Through Disabled\n- [ ] Disable tap-through mode\n- [ ] Tap anywhere on overlay\n- [ ] Overlay intercepts all taps\n- [ ] Underlying app does NOT receive taps\n\n---\n\n## 7. Visibility Toggle\n\n### 7.1 Toggle via Outside Tap\n- [ ] Enable tap-through mode\n- [ ] Tap outside image bounds\n- [ ] Image visibility toggles (visible → hidden)\n- [ ] Tap outside image again\n- [ ] Image visibility toggles (hidden → visible)\n- [ ] Underlying app still receives all taps\n\n### 7.2 Toggle Smoothness\n- [ ] Visibility toggle uses fade animation (0.15s)\n- [ ] Animation is smooth (no jank)\n- [ ] Animation respects previous state correctly\n\n### 7.3 Rapid Toggling\n- [ ] Tap multiple times rapidly outside image\n- [ ] Overlay toggles correctly each time\n- [ ] No crashes or state corruption\n\n---\n\n## 8. System Integration\n\n### 8.1 App Switching\n- [ ] Open app (e.g., Safari)\n- [ ] Overlay visible above app\n- [ ] Switch to another app (e.g., Messages)\n- [ ] Overlay still visible above new app\n- [ ] Switch back to original app\n- [ ] Overlay still visible at original position/scale\n\n### 8.2 Multi-Tasking (Split View)\n- [ ] Enable split view (if supported)\n- [ ] Open two apps side-by-side\n- [ ] Overlay should still be visible (verify it doesn't interfere with split view UI)\n- [ ] Tap and drag overlay between apps\n\n### 8.3 Notifications\n- [ ] While overlay visible, trigger notification (e.g., SMS)\n- [ ] Notification banner appears above overlay (or at least visible)\n- [ ] Overlay does not block notification\n- [ ] Tap notification to open app\n- [ ] Overlay persists when app opens\n\n### 8.4 Control Center & Notifications Center\n- [ ] Swipe from top to open Notification Center\n- [ ] Notification Center appears above overlay\n- [ ] Overlay does not interfere\n- [ ] Close Notification Center\n- [ ] Overlay still visible\n\n---\n\n## 9. Performance & Stability\n\n### 9.1 Frame Rate\n- [ ] Use \"Developer\" → \"Color Blended Layers\" (Xcode simulator or device with developer tools)\n- [ ] Drag image: maintain 60 FPS (or 120 FPS on ProMotion)\n- [ ] Pinch image: maintain 60 FPS (or 120 FPS)\n- [ ] No dropped frames during interaction\n\n### 9.2 CPU & Memory Usage\n- [ ] At idle (overlay visible, no interaction): CPU < 1%, Memory < 10 MB\n- [ ] During drag: CPU < 8%, Memory stable\n- [ ] During pinch: CPU < 8%, Memory stable\n- [ ] After 1 hour of inactivity: Memory not growing (no leak)\n\n### 9.3 Battery Impact\n- [ ] Keep overlay visible for 30 minutes\n- [ ] Monitor battery drain: should be minimal (< 2% for 30 min)\n- [ ] Disable overlay and repeat: battery drain should decrease\n\n### 9.4 Stability\n- [ ] Overlay active for 2+ hours: no crashes\n- [ ] Perform 50+ drag operations: no crashes\n- [ ] Perform 50+ pinch operations: no crashes\n- [ ] Switch apps 20+ times: no crashes\n\n---\n\n## 10. Edge Cases\n\n### 10.1 Large Image\n- [ ] Select very large image (e.g., 4000x3000 px)\n- [ ] Image displays without hang\n- [ ] Initial load time < 2 seconds\n- [ ] Drag/pinch remains smooth\n\n### 10.2 Small Image\n- [ ] Select very small image (e.g., 64x64 px)\n- [ ] Image displays correctly (scaled up to fit)\n- [ ] No distortion\n\n### 10.3 Device Rotation\n- [ ] Overlay visible in portrait\n- [ ] Rotate device to landscape\n- [ ] Overlay reposition/adjust appropriately (verify overlay doesn't go off-screen)\n- [ ] Rotate back to portrait\n- [ ] Overlay returns to original position\n\n### 10.4 Low Memory Warning\n- [ ] Simulate low memory (if possible)\n- [ ] Overlay should not crash\n- [ ] State should be saved immediately\n- [ ] Overlay should remain functional after recovery\n\n### 10.5 Photos Denied\n- [ ] Revoke Photos permission in Settings\n- [ ] Try to open image picker\n- [ ] Should show graceful error (not crash)\n- [ ] User can re-enable permission and try again\n\n### 10.6 Very Rapid Drag & Pinch\n- [ ] Drag image rapidly across screen\n- [ ] Pinch rapidly (zoom in/out fast)\n- [ ] Combine: drag + pinch simultaneously\n- [ ] No crashes, state remains correct\n\n---\n\n## 11. System Safety\n\n### 11.1 No Code Injection into Apps\n- [ ] Open app with overlay visible\n- [ ] Verify app functions normally\n- [ ] Verify no tweak code running in app context\n- [ ] Check `/var/log/system.log` for no injection errors\n\n### 11.2 No Keyboard Interception\n- [ ] While overlay visible, tap on text field in app\n- [ ] Keyboard appears normally\n- [ ] Can type without overlay interfering\n- [ ] Overlay does not capture keyboard events\n\n### 11.3 No Screen Recording Interception\n- [ ] Start screen recording (or screen mirroring)\n- [ ] Overlay should still function (not disabled)\n- [ ] Recording should not capture overlay (or should, depending on design)\n\n### 11.4 No Memory Corruption\n- [ ] After 2+ hours of activity, check system stability\n- [ ] No random crashes in other apps\n- [ ] System remains responsive\n\n---\n\n## 12. UI/UX Quality\n\n### 12.1 Animations\n- [ ] Fade In animation smooth (0.15s)\n- [ ] Fade Out animation smooth (0.15s)\n- [ ] Animations start/end at correct opacity values\n\n### 12.2 Gesture Feedback\n- [ ] Drag provides immediate visual feedback\n- [ ] Pinch provides immediate visual feedback\n- [ ] No lag between touch and response\n\n### 12.3 Touch Responsiveness\n- [ ] All touches respond within 100ms\n- [ ] No \"dead zones\" on overlay\n- [ ] Gesture recognition is reliable (>95% success)\n\n---\n\n## 13. Regression Testing\n\n### 13.1 After Each Build\n- [ ] Tweak still loads without crash\n- [ ] Image still displays\n- [ ] Drag works\n- [ ] Pinch works\n- [ ] State persists\n\n### 13.2 After Any Code Change\n- [ ] Run full test suite (all sections above)\n- [ ] No new crashes introduced\n- [ ] No performance regression\n\n---\n\n## Test Results Template\n\n```\n### Test Session: [Date & Time]\n**Tester**: [Name]\n**Device**: [Model, iOS Version]\n**Build**: OverlayImage v[Version]\n\n**Overall Status**: [PASS / FAIL / PARTIAL]\n\n**Results**:\n1.
